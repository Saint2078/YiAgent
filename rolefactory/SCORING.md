# 客观评分体系（objective scoring）

给「某个角色的 Agent 到底行不行」一个**可复算**的分数：同一份回答，任何时候、任何人跑都得同一分。
实现在 `app/objective.py`，自测在 `tests/test_objective.py`（`python tests/test_objective.py`）。

## 为什么不用 LLM 裁判打主分

2026-08-09 首轮实跑（角色「数据分析专家」，k3 自评）的实测问题：

- 分数堆在 86–94，σ<1；基线（完全无基因）都能拿 86.42。
- 冠军相对「全弱基因」只 +0.42 —— 分差主要来自「有没有提示词」，不来自基因质量。
- holdout 上冠军 −0.35 于基线，第 1 代反而差于第 0 代。搜索信号被裁判噪声吃掉了。

结论：**同族模型自评存在天花板**，不适合当选种信号。所以把判分从「模型评价」换成「程序校验」。

## 三条铁律

1. **判分不过模型**。LLM 只做两件事：出题、作答。打分是纯 Python，无随机性、无网络。
2. **题面自带全部数据**。关键结论必须能由题面数字用四则运算算出，不许联网/读文件/跑代码。
3. **标准答案要自校**。出题时必须同时给算式 `computation`，程序复算若与 `target` 不一致（相对误差 >1%），
   该题**判为出题错误并丢弃重出**（最多 3 次）。宁可少一道题，不要用错的答案打分。

## check 类型

| 类型 | 判什么 | 关键字段 | 给分 |
|------|--------|----------|------|
| `numeric` | 关键数值算对 | `target` `tolerance` `unit` `near` `computation` | 0/1 |
| `must_include` | 必须覆盖的要素（每组同义词任中一个即算命中） | `groups[{label, any[]}]` | 命中组数 / 总组数 |
| `must_not_include` | 禁止出现的错误断言或错误数值 | `groups[{label, any[]}]` | 命中即 0，否则 1 |
| `ask_back` | 信息不足时必须回问 | `groups`（缺口关键词） | 缺口覆盖率 ×（有问号 1.0 / 无 0.5）|
| `min_items` | 必须列够条数 | `min` | min(1, 实际条数/要求) |
| `lead_with` | 结论先行 | `groups` `first_chars` | 0/1 |
| `regex` | 自定义模式 | `pattern` | 0/1 |

总分 = Σ(weight × 该 check 得分) / Σweight × 100。

## 判分前的归一化

全角转半角（含数字与 `％`）、去 markdown 装饰符、千分位逗号、`万/亿/千/k/M` 量级换算、
百分数与小数互认（`25%` ≡ `0.25`）。`near` 提供定位词时，只在定位词 ±90 字窗口内找数值，
避免「文中随便有个 25」被误判为算对。

## 防作弊与已知边界

- **堆词**：`must_include` 靠关键词，理论上可以堆词蒙分。压制手段：`numeric` 权重不低于 35（算不对拿不到）、
  强制一条 `must_not_include`（说错话直接扣光）、`near` 窗口限制。**不能完全排除**，写进报告 caveats。
- **同义词覆盖不全**：会把对的答案判错（假阴性）。缓解：出题时要求给出多种真实中文表述与英文术语；
  逐条明细会写出「缺哪一组」，可人工回看 `results.jsonl` 里的原文核对。
- **题目仍由 LLM 生成**：`computation` 重算只能保证算术自洽，保证不了业务口径设计得好。
- 样本量小时分差要连同 `σ`、`spread`、`paired` 一起读，不做显著性声明。

## 与主观裁判的对照（已实测）

同一次 run 里可以开 `judge_shadow`（默认开）：在**基线阶段与 holdout 阶段**额外跑一遍 LLM 裁判，
分数记在 `judge_score`，**不参与选种**，只用来对比两种口径的区分度（报告里的
`objective_spread_arms` vs `judge_shadow_spread_arms`）。

对已完成的 run 也可以补跑：`POST /api/run/{id}/shadow`（直接复用 `results.jsonl` 里存下来的回答，
不重新作答），结果落在 `data/runs/{id}/shadow.json`。

角色「产品分析专家」run `20260808-183754-70aab5`，**同一批 40 条回答**两种口径并列：

| 口径 | 基线均分 | 冠军均分 | 臂间差 | 分布范围 |
|------|---------|---------|--------|---------|
| 客观（程序校验） | 84.71 | 91.08 | **6.37** | 53.33 – 100 |
| 主观（LLM 裁判） | 91.52 | 92.99 | **1.47** | 77.35 – 99 |

- 客观口径的臂间差是主观口径的 **4.3 倍**；主观裁判把下限从 53 抬到 77，好坏被压平。
- 行级相关性只有 **0.304**，两种口径基本在测不同的东西。
- 有 **2 条**回答被裁判打 ≥90 而客观分 <70（`judge_high_objective_low`），即放水样本。

所以选种信号用客观分，主观分只作旁证。

## 怎么用

```bash
curl -X POST http://127.0.0.1:8790/api/run -H "Content-Type: application/json" \
  -d '{"role":"产品分析专家","scoring_mode":"objective","per_dim":2,"reps":2}'
```

`scoring_mode` 默认 `objective`；传 `judge` 可切回主观 rubric 模式做对照实验。
